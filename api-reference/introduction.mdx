The Vivix API is a unified REST interface for building interactive avatar experiences. Both product lines — Streaming Avatar and Blazing Fast Video Generation — share the same base URL, the same API key authentication scheme, and the same response envelope format. This page covers the basics you need before calling any endpoint.

## Base URL

All API requests are made to the following base URL:

```
https://api.vivix.ai
```

Every endpoint path in this reference is relative to this base URL. For example, the full URL to create a Streaming Avatar session is `https://api.vivix.ai/v1/streaming-avatar/sessions`.

## Authentication

Authenticate your requests by including your API key in the `Authorization` header:

```http
Authorization: Bearer <API_KEY>
```

You must send this header on every server-side request. Your API key grants access to all endpoints enabled for your account — treat it like a password.

<Warning>
  Never send your API key to a browser or mobile client. All requests that include `Authorization: Bearer <API_KEY>` must originate from your own backend server. The only credentials that are safe to forward to a browser are `control.client_secret` and the TRTC media credentials returned during Streaming Avatar session creation.
</Warning>

For full details on key management and browser-safe credentials, see the [Authentication](/authentication) page.

## Response Envelope

Every response from the Vivix API — success or error — is wrapped in the same JSON envelope:

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

<ResponseField name="code" type="integer">
  Status code for the operation. `0` indicates success. Any non-zero value indicates an error — check `message` for a human-readable description.
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable status message. `"ok"` on success; a description of the error on failure.
</ResponseField>

<ResponseField name="data" type="object | null">
  The response payload for the request. `null` on endpoints that return no data (such as closing a session).
</ResponseField>

## Rate Limits

The Vivix API enforces rate limits to ensure fair usage across all customers. When you exceed a rate limit, the API returns an HTTP `429 Too Many Requests` response.

<Note>
  If you receive a `429` response, implement exponential backoff before retrying. Start with a short delay (for example, one second), then double the delay on each subsequent retry up to a maximum interval. Avoid retrying immediately in a tight loop, as this will continue to trigger the rate limit.
</Note>

Contact [Vivix support](mailto:support@vivix.ai) if your use case requires higher rate limits than your current plan provides.
